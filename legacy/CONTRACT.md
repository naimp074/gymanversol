# Anversol — implementation contract

Local Node 22.18+ server, node:sqlite database, dependency-free HTML/CSS/ES modules. All assets local. Spanish UI, ARS amounts stored as integer pesos. No automatic demo login; first-run setup creates owner and optionally sample data. Server timezone America/Argentina/Buenos_Aires; YYYY-MM-DD for dates. Runtime default 127.0.0.1:3000; explicit HOST=0.0.0.0 enables LAN.

## HTTP
All JSON endpoints return actual object/array, errors `{error}` and correct HTTP code. Cookie session HttpOnly SameSite=Strict. Mutations require same-origin checking. `GET /api/session` -> `{user:null|{id,name,username,role},needsSetup:boolean}`. `POST /api/setup {name,username,password,demo:boolean}` -> `{user}`. `POST /api/login {username,password}` -> `{user}`; `POST /api/logout`.

`GET /api/bootstrap` -> `{user,today,settings,members,plans,checkins,payments,movements,cashSessions,products,sales,teachers,classes,reservations,routines,measurements,users,audit,backups}`. Arrays excluded by role may be empty. Member computed properties `status` (activo,vencido,suspendido,baja), `daysLeft`, `planName`, `lastCheckin`. Keep archived member state separately in `state` (activo,suspendido,baja). Every entity has string `id`, `createdAt`.

Generic POST `/api/:collection`, PUT `/api/:collection/:id` for members, plans, products, teachers, classes, routines, measurements, users. Response saved entity. DELETE only where safe: reservations/routines/classes and users (deactivate instead preferred). All writes audited; no deleting finance. Roles `dueno`, `administrador`, `recepcionista`, `profesor`, `contador`; backend checks obligatory.

Members: `{name,dni,birthDate,phone,whatsapp,email,address,photo,joinedAt,number,state,planId,expiresAt,lastPayment,notes,emergencyName,emergencyPhone,medicalExpiresAt,medicalFile,medicalFileName,qrToken}`. photo and medicalFile local data URLs (size/type limits); qrToken server-generated opaque token. New member without paid membership stays expired unless valid expiresAt explicitly set by admin. Phone optional. Number auto generated. No simulated fingerprint enrollment.

Plans: `{name,price,duration,accessLimit,startTime,endTime,discount,description,active}`; duration days positive, accessLimit 0 unlimited, discount percentage 0..100. Default hours 06:00..23:00.

POST `/api/payments {memberId,planId,method,discount:0}` -> `{payment,member}`. Server computes price/discount and expiry max(today,existing future expiry)+duration days. methods `Efectivo`, `Transferencia`, `Mercado Pago`, `Débito`, `Crédito`. Open cash session required. Creates payment + movement atomically; no client-trusted amount. Discount admin only when >0. Payment `{memberId,planId,amount,method,date,expiresAt,userId}`.

POST `/api/checkins {identifier,method:'manual'|'qr',override:false}` -> `{checkin,member,allowed,reason}`. Exact lookup dni/number/id or qrToken. Enforce suspended/baja, expiry, plan hours/access limit, medical expiry if settings.requireMedical. Rejected attempts logged allowed=false. Reception/admin may override expired membership only when configured. Prevent duplicate admitted open entry. POST `/api/checkins/:id/checkout` -> checkin. Checkin `{memberId,date,allowed,reason,method,checkoutAt}`. All stats count allowed only.

POST `/api/cash/open {openingAmount}`; POST `/api/cash/close {countedAmount,notes}`. Cash session `{openedAt,closedAt,openingAmount,countedAmount,expectedAmount,difference,userId}`. One shared active register. Expected cash uses Efectivo movements only plus opening. POST `/api/movements {type:'ingreso'|'gasto'|'retiro',category,description,amount,method}`. Positive amounts; type determines sign; open session required. Movement `{type,category,description,amount,method,date,sessionId,userId}`. Closing cashier allowed reception/accountant/admin.

POST `/api/sales {items:[{productId,quantity}],method}` computes prices/stock, atomic stock deduction + sale + movement; open session required. POST `/api/sales/:id/void {reason}` admin only, compensates stock/cash atomically without deleting original. Products `{name,category,price,cost,stock,minStock,active}`. Sale `{items,total,method,date,voided}`.

Teachers `{name,phone,specialty,schedule,salary,state}`. Classes `{name,teacherId,date,time,duration,capacity,description}`; one dated session. Reservations POST `/api/reservations {classId,memberId}` capacity + duplicate check + active membership; DELETE `/api/reservations/:id`.

Routines `{memberId,teacherId,name,goal,days,notes}`; days plain multi-line training text. Measurements `{memberId,date,weight,height,waist,arm,chest,leg,bodyFat,photo,notes}`; height centimeters, optional fields.

Users `{name,username,role,password,active}`; NEVER return password hash. Owner/admin manages, last owner protected. Role professor cannot access payments/movements/salaries/medical files; training/member/basic attendance access only. Settings `{gymName,allowExpiredOverride,allowExpiredEntry,requireMedical,address,phone}` GET in bootstrap; PUT `/api/settings` admin.

GET `/api/export?type=members|payments|movements|checkins|products|sales&from=YYYY-MM-DD&to=YYYY-MM-DD` CSV BOM + delimiter semicolon, formula injection protection. Reports printable HTML via UI browser print Save PDF. POST `/api/backups` creates SQLite backup VACUUM INTO; GET `/api/backups/:name` download restricted basename; daily automatic backup + retention 14. `backups` list `{name,date,size}`. Audit `{date,userId,userName,action,entityId,detail}` read-only.

## Frontend shared API
Root owns public/index.html, public/styles.css, public/app.js, public/core.js. Extra modules agent owns public/modules.js only, imports from core.js: `state` object `.data` bootstrap and `.user`; `api(path, options={})` JSON fetch with options.method/options.body object; `esc(value)`, `money(value)`, `date(value)`, `time(value)`, `icon(name,size=20)`, `badge(text,tone='neutral')`, `avatar(member)`, `toast(message,type='success')`, `modal(title,html,onSubmit,wide=false)` wraps HTML in form and invokes onSubmit(FormData,form), closes and refreshes after successful callback; `closeModal()`, `refresh()` reloads bootstrap then render; `navigate(route)`, `memberName(id)`, `empty(message)`, `field(label,name,type='text',value='',extra='')`, `selectField(label,name,options,value='')` with options array {value,label}; `confirmAction(title,message,asyncCallback)` modal.

modules.js exports `renderModule(route)` HTML for routes `planes`, `caja`, `productos`, `ventas`, `profesores`, `clases`, `rutinas`, `progreso`, `reportes`, `configuracion`, `auditoria`; `handleModuleAction(action,id,element)` async boolean handles delegated clicks attributes data-action/data-id; `afterModuleRender(route)` for dynamic UI setup. Use `data-action` and `data-id` on buttons. Classes shared: `.card`, `.card-head`, `.card-title`, `.muted`, `.btn`, `.btn-primary`, `.btn-secondary`, `.btn-sm`, `.btn-danger`, `.grid-2`, `.grid-3`, `.stats-grid`, `.stat-card`, `.stat-value`, `.stat-label`, `.toolbar`, `.table-wrap`, `.data-table`, `.form-grid`, `.full`, `.badge`, `.badge-green`, `.badge-amber`, `.badge-red`, `.badge-neutral`, `.avatar`, `.page-heading`, `.section-title`, `.stack`, `.empty`, `.detail-grid`. Root owns routes `inicio`, `socios`, `accesos`, `vencimientos`, `asistencia`, `comunicaciones`, and members/payment modal actions. Modules may use action `member-detail`, `payment`, `member-new` handled by root. Root outer page renders page heading based on route; module should not repeat h1.

No outbound messaging executed: WhatsApp buttons open composed wa.me draft for user to review/send. No cloud backup/payment/biometric claims without real integration. README covers boundaries and operational setup.
